The `ai/jev` component: integrates the System One model (Jev) from [TypeSafe AI](https://typesafe.ai/) — **ask one question, route by the answer**. A sibling of [Intent Recognition](/en/pages/ai-intent/) (LLM generative classification) and [Local Intent Recognition](/en/pages/ai-local-intent/) (embedding similarity). For pure yes/no guards (True/False) use the standalone [Jev Filter](/en/pages/ai-jev-filter/).

Jev generates no text. It outputs structured decisions with calibrated confidence at 70~500ms latency and roughly two orders of magnitude cheaper than LLM classification — suitable for online decision points every message can afford: intent routing, risk gating, alarm grading.

## Usage

Fill in one **question** and a list of **options**, then draw one line per option name on the canvas. Done.

Three answer types:

| Type | Fill in | Routing |
|------|------|------|
| `choice` options (default) | question + options (name + description) | Route by winning option name |
| `noul` yes/no | question (treated as a statement) | `True` / `False` lines |
| `score` levels | question + ordered level list | Route by nearest level name; metadata carries the continuous score |

## Configuration

| Field | Type | Description | Default |
|------|------|------|--------|
| url | string | System One endpoint; point to a proxy gateway if unreachable | `https://api.typesafe.ai/v1/systemone` |
| key | string | API key, supports `${global.xxx}` templates | |
| model | string | Model name | `jev-latest` |
| input | string | Content to evaluate, supports `${msg.key}` and `${metadata.key}`. Empty uses `msg.GetData()` | |
| question | string | The question to ask about the input | |
| answerType | string | `choice` / `noul` / `score` | `choice` |
| options | []Option | Option list. Route relations for choice; ordered rubric for score (2-10 levels); ignored by noul | |
| extraQuestions | []ExtraQuestion | Optional extra questions: evaluated in parallel with the main question in one request; answers are tagged only, never affect routing | |
| outputTo | string | Where results go: `metadata` writes to msg.Metadata (default, payload untouched); `data` (alias `msg`) replaces msg.Data with the results JSON object | `metadata` |
| minConfidence | float | Answers below this confidence route to the `Default` line instead | 0.5 (negative disables) |

Timeout (10s), overload retries (2, exponential backoff), gate threshold (0.5) and state form (auto JSON detection) are fixed defaults, not exposed as config.

### Option structure

| Field | Description |
|------|------|
| name | Option/level name, used as the route relation type |
| description | What the option/level means, helps the model decide |

### ExtraQuestion structure

| Field | Description |
|------|------|
| id | Metadata key for the answer (`jev.<id>`), cannot be `answer` |
| type | `choice` / `noul` / `score` |
| question | The question to ask |
| options | Same Option structure as the main question; ignored by noul |

Extra questions fit triage scenarios that need several dimensions tagged at once (urgency + severity + department): all questions are evaluated **in one request in parallel** with negligible latency cost.

The division of labor: **the main question drives the lines; extra answers are only for reading** — downstream reads `${metadata.jev.<id>}` (or `${msg.<id>}` in data mode). A missing extra answer is skipped silently and never affects routing.

### Result output (outputTo)

- `metadata` (default): all answers go to `msg.Metadata`, `msg.Data` passes through untouched
- `data` (alias `msg`): `msg.Data` is replaced by the results JSON object (`answer`, `<id>` extra answers, `model`, `usage`, native types) — useful when the analysis itself is the chain's output, e.g. an HTTP endpoint response; use `metadata` to keep the original message

## Execution Result

- With `outputTo=metadata` `msg.Data` is untouched and passed downstream; with `data` the payload is replaced by the results object
- `jev.answer`: primary value (option name / 0~1 probability / continuous score)
- `jev.answer.confidence`, `jev.answer.probabilities`: confidence and distribution
- `jev.level`: nearest level name for score
- `jev.model`, `jev.usage`: model and token usage

## Examples

### Intent routing (choice)

```json
{
  "id": "node_jev_1",
  "type": "ai/jev",
  "name": "Ticket Triage",
  "configuration": {
    "key": "${global.typesafeKey}",
    "question": "Pick the intent that best matches the input",
    "options": [
      {"name": "billing", "description": "Invoices and charges"},
      {"name": "technical", "description": "Bugs and integration"},
      {"name": "sales", "description": "Pre-sales"}
    ]
  }
}
```

### Risk gating (noul)

```json
{
  "id": "node_jev_2",
  "type": "ai/jev",
  "name": "Destructive Command Guard",
  "configuration": {
    "key": "${global.typesafeKey}",
    "question": "The command modifies or deletes data and is destructive",
    "answerType": "noul"
  }
}
```

### Alarm grading (score)

```json
{
  "id": "node_jev_3",
  "type": "ai/jev",
  "name": "Alarm Grading",
  "configuration": {
    "key": "${global.typesafeKey}",
    "question": "Rate the severity of the alarm",
    "answerType": "score",
    "options": [
      {"name": "info", "description": "No action needed"},
      {"name": "warning", "description": "Watch by operator"},
      {"name": "high", "description": "Handle soon"},
      {"name": "critical", "description": "Act immediately"}
    ]
  }
}
```

### Extra questions + payload output (data)

```json
{
  "id": "node_jev_4",
  "type": "ai/jev",
  "name": "Ticket Triage",
  "configuration": {
    "key": "${global.typesafeKey}",
    "question": "Pick the intent that best matches the input",
    "answerType": "choice",
    "options": [
      {"name": "billing",   "description": "Invoices and charges"},
      {"name": "technical", "description": "Bugs and integration"},
      {"name": "sales",     "description": "Pre-sales"}
    ],
    "extraQuestions": [
      {"id": "isUrgent", "type": "noul", "question": "The message conveys urgency"},
      {"id": "severity", "type": "score", "question": "Rate the severity",
       "options": [
         {"name": "low", "description": "Routine"},
         {"name": "medium", "description": "Affects some users"},
         {"name": "high", "description": "Production incident"}
       ]}
    ],
    "outputTo": "data"
  }
}
```

All three questions run in one parallel request; routing still follows the `billing`/`technical`/`sales` lines, and the payload is replaced by the result object — a typical HTTP endpoint response:

```json
{
  "answer": "technical",
  "answer.confidence": 0.9,
  "isUrgent": 0.99,
  "severity": 2,
  "severity.confidence": 0.9,
  "model": "jev-1.13.0",
  "usage": {"input": 392, "output": 65}
}
```

### Low-confidence cascade

Answers below 0.5 confidence go to the `Default` line — that line belongs exclusively to low-confidence answers (normal answers take the option / True / False / level lines). Wire it to an [ai/agent](/en/pages/ai-agent/) node for the cascade pattern: Jev handles the confident majority, the LLM only sees the uncertain minority.

## Notes

- Get an API key at [console.typesafe.ai](https://console.typesafe.ai/keys)
- The query API has no side effects; 429/529 overload is retried with exponential backoff
- Benchmark non-English questions before relying on them in production
