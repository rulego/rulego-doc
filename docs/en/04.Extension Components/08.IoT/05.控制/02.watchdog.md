`x/control/watchdog` component: a watchdog that monitors message-flow continuity. Every arriving message is forwarded downstream and re-arms the timer; if no message arrives within the timeout, a preconfigured failsafe JSON payload (e.g. close valve, stop motor) is emitted downstream. Protocol-agnostic, it is typically wired in series in front of `x/iotWrite` for host-link loss protection.

> Additional extension library required: [rulego-components-iot](https://github.com/rulego/rulego-components-iot)

## Configuration

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| timeout | string | Yes | Watchdog timeout, e.g. `10s`, `500ms`; supports `${metadata.xx}` templates |
| failsafe | object | No | JSON payload emitted downstream on timeout, e.g. `{"valve":0,"motor":0}`; written to `msg.Data` and forwarded via the `Success` chain |

## Behavior

- Message received: the original message is forwarded downstream and the timer is re-armed.
- `timeout` reached without any message: the `failsafe` JSON is emitted via the `Success` chain.

## Relation Type

- ***Success:*** Message forwarded, or the failsafe payload emitted.
- ***Failure:*** Execution fails; the message is sent to the `Failure` chain.

## Example

```json
{
  "ruleChain": {
    "id": "watchdog_demo",
    "name": "Watchdog failsafe demo",
    "root": true,
    "debugMode": false
  },
  "metadata": {
    "firstNodeIndex": 0,
    "nodes": [
      {
        "type": "x/control/watchdog",
        "name": "Host link-loss protection",
        "debugMode": false,
        "configuration": {
          "timeout": "10s",
          "failsafe": {"valve": 0, "motor": 0}
        }
      }
    ],
    "connections": []
  }
}
```
