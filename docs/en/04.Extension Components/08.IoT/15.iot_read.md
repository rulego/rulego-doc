`x/iotRead` component: <Badge text="v0.35.0+"/> **universal acquisition entry**. Switches the protocol backend by `driver` (modbus / s7 / eip / snmp / opcua); configuration is passed through to the corresponding protocol read node. Output is unified to `iot_points.Data`, decoupled from any specific protocol — switch backends by changing only `driver` and that protocol's connection/point config, with the rest of the chain unchanged.

> Requires the extension library: [rulego-components-iot](https://github.com/rulego/rulego-components-iot)

## Configuration

| Field | Type | Description | Default |
|---|---|---|---|
| driver | string | Acquisition backend: `modbus` / `s7` / `eip` / `snmp` / `opcua` | none (required) |
| ...（passthrough） | - | The selected protocol's connection/point config, passed as-is to its read node | - |

Backend mapping:

| driver | Actual node | Key config |
|---|---|---|
| modbus | x/modbusReadPoints | server / unitId / points(addr=Modicon) |
| s7 | x/s7Read | server / rack / slot / points |
| eip | x/eipRead | server / slot / points |
| snmp | x/snmpRead | server / points(addr=OID) |
| opcua | x/opcuaRead | server / policy / points(addr=NodeID) |

## Output

Unified contract `iot_points.Data` (same as the protocol read nodes):

```json
[{"name": "temp", "value": 23.5, "timestamp": 1789999999000000000}]
```

## Example

```json
{
  "id": "read",
  "type": "x/iotRead",
  "configuration": {
    "driver": "modbus",
    "server": "tcp://192.168.1.100:502",
    "unitId": 1,
    "points": [{"name": "temp", "addr": "40001", "type": "FLOAT32"}]
  }
}
```
