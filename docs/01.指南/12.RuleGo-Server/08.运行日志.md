RuleGo-Server 提供规则链执行日志的持久化存储和查询能力，支持多种存储后端。

## 配置

```ini
# 运行记录级别：off（不记录，默认）/ summary（摘要）/ detail（完整节点日志）
# 替代原 save_run_log，链级 additionalInfo.runLogMode 可覆盖此全局配置
run_log_mode = summary
# 存储后端类型：bbolt（默认）、file
run_log_store_type = bbolt
# 每条规则链保留最近 N 条日志，0 表示不限制
run_log_retention_count = 500
# 保留最近 N 天日志，0 表示不限制
run_log_retention_days = 7
```

运行记录级别说明：

| 级别 | 说明 |
|------|------|
| `off` | 不记录运行日志（默认） |
| `summary` | 只记录执行摘要（开始/结束时间、状态、耗时），不收集逐节点日志，近零开销 |
| `detail` | 记录完整逐节点日志，可在执行历史中查看每个节点的详细执行步骤 |

规则链级别的 `additionalInfo.runLogMode`（`off` / `summary` / `detail`）可覆盖全局配置，实现按链粒度的日志策略。

## 存储后端

| 类型 | 说明 | 适用场景 |
|------|------|----------|
| `bbolt` | 内嵌键值数据库（默认） | 生产环境，性能好 |
| `file` | JSON Lines 文件存储 | 调试、日志导出 |

> `run_log_mode = off` 时内部自动使用空存储，无需额外配置。

## 查询执行历史

```http
GET /api/v1/logs/runs?chainId={chainId}&page=1&size=20&startTime=&endTime=
Authorization: Bearer {token}
```

查询参数：

| 参数 | 类型 | 说明 |
|------|------|------|
| `chainId` | string | 规则链 ID 过滤 |
| `id` | string | 指定运行记录 ID |
| `page` | int | 页码 |
| `size` | int | 每页数量 |
| `startTime` | string | 开始时间过滤 |
| `endTime` | string | 结束时间过滤 |

## 获取单条记录

```http
GET /api/v1/logs/runs?id={runId}
Authorization: Bearer {token}
```

## 删除记录

```http
# 按规则链删除
DELETE /api/v1/logs/runs?chainId={chainId}

# 按记录 ID 删除
DELETE /api/v1/logs/runs?id={runId}
Authorization: Bearer {token}
```

## 节点调试数据

获取规则链节点的调试日志：

```http
GET /api/v1/logs/debug?chainId={chainId}&nodeId={nodeId}
Authorization: Bearer {token}
```

节点调试日志的记录由 `debug` 和 `max_node_log_size` 配置控制：

```ini
# 是否把节点调试日志打印到日志文件
debug = true
# 每个节点最大日志条数
max_node_log_size = 40
```

## 在编辑器中查看

- **调试控制台**：底部面板实时显示节点 IN/OUT 数据
- **节点调试面板**：点击节点查看历史调试日志
- **执行历史**：运行对话框中查看历史执行记录
