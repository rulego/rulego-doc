`ai/jevFilter` 组件：判断一句话对消息内容是否成立，**成立走 `True`，不成立走 `False`**。是 [jsFilter](/pages/js-filter/) 语义的智能版——把"写代码判断"换成"写一句陈述"，由 [Jev](/pages/ai-jev/)（System One 是否型问题）判断。

适合语义规则写不出来的过滤：命令是否具有破坏性、内容是否违规、客户是否表达了不满等。延迟 70~500ms、近零成本，可放在每条消息都经过的位置。

## 配置

| 字段 | 类型 | 说明 | 默认值 |
|------|------|------|--------|
| url | string | System One 端点 | `https://api.typesafe.ai/v1/systemone` |
| key | string | API Key，支持 `${global.xxx}` 模板 | |
| model | string | 模型名 | `jev-latest` |
| input | string | 要判断的内容，支持 `${msg.key}` 和 `${metadata.key}`。为空时使用 `msg.GetData()` | |
| question | string | 要判断的一句话（陈述） | |

## 执行结果

- `True` / `False` 两条路由线（概率 ≥ 0.5 走 True），出错走 `Failure`
- `jevFilter.answer`：成立的概率（0~1，如 `0.95`，接近 0.5 的边界值可做二次判断）
- `jevFilter.model`、`jevFilter.usage`：模型与 token 消耗
- 不修改 `msg.Data`

## 配置示例

```json
{
  "id": "node_jev_filter",
  "type": "ai/jevFilter",
  "name": "危险命令守卫",
  "configuration": {
    "key": "${global.typesafeKey}",
    "question": "该命令会修改或删除数据，具有破坏性"
  }
}
```

`False` 线直连执行节点，`True` 线先走人工确认或审批链。

## 与 ai/jev 的关系

`ai/jevFilter` 等价于 [ai/jev](/pages/ai-jev/) 的 `answerType: "noul"` 形态，独立成组件是为了：

- 固定的 True/False 契约与 jsFilter 一致，组件库可直接声明连线类型
- 表单只有 5 个字段，守卫场景零学习成本
- metadata 前缀为 `jevFilter`，与 `ai/jev` 同链共存不冲突

需要多选项路由或档位评分时用 [ai/jev](/pages/ai-jev/)。
